# dsh-video-understanding

让 DSH 按**画面累计变化量**决定看多密：变化攒够了才取一帧，一秒攒够几次就拼一张宫格。

不是"每 N 秒一帧"，也不是"先抽满再去重"，而是把变化量当电量来攒 —— 安静处几秒才落一帧，猛变处一秒落好几帧，转场和硬切一定留痕。

## 它解决的问题

等分抽帧会把 20 秒的长镜头白白占掉 10 帧，同时跨过两处 0.3 秒的快闪；全量密采再删则慢到原片的 1.5 到 3 倍。

这里把"取帧密度"直接挂在"画面变了多少"上，并且让这个关系可算、可复现、可截断：

```
变化率低  ──  攒 0.3 个满屏变化要 8 秒  ──  8 秒一帧
变化率高  ──  攒 0.3 个满屏变化要 0.1 秒 ──  一秒十帧，拼 4x4
```

## 三个工具

| 工具 | 干什么 | 视觉 token |
|---|---|---|
| `video_plan` | 只扫描不取图：报时长、切点数、密度地图、要几张图、大概多少钱 | **0** |
| `video_watch` | 按计划交付宫格图 + 时间码清单 + 字幕 | 每张图约 233 |
| `video_closeup` | 按时间码取回全分辨率单帧 | 约 233 到 384 |

先 `video_plan` 看计划，再决定要不要 `video_watch`；某格糊得看不清，用 `video_closeup` 对着时间码取原图。

## 采样计划是怎么算出来的

全在 `lib/plan.js` 里，纯函数，可离线断言。

1. **扫描**：整片解码一次，按 10 fps、长边 120 px 存成 raw RGB，逐帧算**面积变化分** `d`：
   画面切成 4×4 方块，块内平均色差超过 8/255 的方块占比，取值 0 到 1。
   `d = 0.12` 直接读作"12% 的画面变了"，和"累积变化量"是同一个量纲。
2. **死区**：低于噪声底的变化当 0，高于的按原值计入。噪声底取低分位（封顶 2%），
   只用来吃掉颗粒和压缩噪声。用"相减"会出事：一条全程每帧 3% 面积变化的片子，
   低分位也是 3%，相减后什么都不剩，整片一帧都抽不出来。
3. **积分**：累积变化量每满 `a` 落一个抽帧时刻，然后清零。**间隔天然等于 `a / 变化率`**，
   不需要 gamma 曲线去压。一个 0.1 秒间隔里攒得下几个 `a` 就落几个时刻（`multiCross`），
   时刻按 `d` 线性插值落在间隔内部；取帧时按**原视频帧率**重取，不受 10 fps 限制。
4. **补帧**：相邻时刻超过 `maxGap` 就在中间插一帧。没有这条，静态幻灯片会留下几十秒的空洞
   （实测 155 秒的讲解片，最大空洞 38 秒，全片只有 9% 的秒上有帧）。
5. **密度定网格**：每 `t` 秒数时刻个数 n —— `n=1` 单帧，`2~4` 用 2×2，`5~9` 用 3×3，`10+` 用 4×4。
6. **窗口内均匀重取**：拼图的格子**按网格均匀取**（`k×k` 格、间距 `t/k²`），不看时刻的具体位置，
   所以同一张拼图里每格时间间隔严格相等。`n` 只负责选档位。
7. **硬切可选取前后两帧**：`cutPair` 打开时，对"单间隔瞬时跳变"取前一帧 + 后一帧。
   判定收得很紧（单帧跳变 ≥ 0.5 且前后两个间隔都低于 0.15），渐变转场永远不会命中 ——
   那些窗口仍然按密度取满格子，转场过程完整保留。
8. **预算按"图"算**：交出去的张数超过 `maxSheets` 就抬 `a` 再走一遍（二分 10 次）。
   一整个 2×2/3×3/4×4 拼图只算**一张**，因为一张图约 384 token，跟里面几格无关 ——
   所以"多少帧"不决定钱，"多少张图"才决定。抬阈值而不是砍尾巴，因为"抽稀"要全局一致。

扫描结果按 `路径 + 大小 + 修改时间 + 分析帧率 + 分析尺寸 + 块参数` 缓存到 `~/.dsh/cache/video-understanding/`。

## 两套预设

| 用途 | `a` | `maxGap` | `maxSheets` | `overflow` | `cutPair` |
|---|---|---|---|---|---|
| 解析 / 复现剪辑与动画手法 | `0.3` | `5` | `8` | `thin` | 开 |
| 普通视频理解（默认） | `1.5` | `8` | `5` | `thin` | 关 |
| 极省 | `10` | `15` | `2` | `stop` | 关 |

## 参数

全部可以在 profile 配置里给默认值，也可以在单次工具调用里临时覆盖。

| 参数 | 默认 | 范围 | 作用 |
|---|---|---|---|
| `a` | `0.3` | 0.01–100 | 攒够几个"满屏变化"落一帧。越小越密 |
| `t` | `1` | 0.2–10 | 密度窗口（秒）。窗口内的时刻数决定网格阶数 |
| `maxGap` | `5` | 0–120 | 超过这么多秒没取帧就强制补一帧；`0` 关闭 |
| `multiCross` | `true` | 布尔 | 允许一个 0.1 秒间隔里落多个时刻。关掉则密度封顶在分析帧率 |
| `cutPair` | `false` | 布尔 | 硬切取前后两帧。只对瞬时跳变生效，不碰渐变转场 |
| `scanFps` | `10` | 1–30 | 分析帧率。只影响变化率的采样密度，不影响出图 |
| `longSide` | `120` | 32–480 | 分析图长边（像素）。1080p ÷ 16 = 120 |
| `block` / `blockThreshold` | `4` / `8` | 2–16 / 1–64 | 面积变化分的方块边长与块级阈值 |
| `maxSheets` | `5` | 1–200 | 单次交付的**图片张数**上限。一个 4×4 拼图也只算一张 |
| `overflow` | `thin` | `thin/stop` | 超预算时：`thin` 全片变稀（仍覆盖全片）/ `stop` 看到上限就停，后面的内容不看 |
| `burn` | `time` | `time/index/none` | 烧进格子角标的时间码 / 序号 |
| `cacheDir` | `~/.dsh/cache/video-understanding` | 绝对路径 | 扫描结果缓存位置 |

> 已删除的参数：`perSheet`、`sparse`（单帧不再装箱，一帧一张图）、`gridMode`（网格阶数完全由密度决定）、`budgetPixels`（固定 1080p）、`maxWidth`（`video_closeup` 取原分辨率）。

## 拼图与 token

一张图花多少 token 取决于像素，不取决于里面几帧。按 42px 网格算 `rows × (cols+1) + 2`，地板 192、天花板 384。现在单张图固定排到 **1920×1080**：

| 图 | 单格尺寸 | token |
|---|---|---|
| 1920×1080（1×1 单帧） | 1920×1080 | **384** |
| 1920×1080（2×2） | 960×540 | 384 |
| 1920×1080（3×3） | 640×360 | 384 |
| 1920×1080（4×4） | 480×270 | 384 |

**网格档位不影响钱，只影响每格清晰度**；钱只跟"有几张图"有关，而 **张数 = 分组数**（密窗口一张、单帧一张、切点一张）。

实测（`node scripts/smoke.mjs <视频>`）：

| 片子 | 形态 | 帧 | 图 | token |
|---|---|---|---|---|
| 24 秒测试片（黑场 / 运动 / 8 次硬切） | 默认 `a=0.3`，`maxSheets=40`（不触顶） | 95 | 17 | 6528 |
| 同上 | `maxSheets=3`，`maxGap=0` | 3 | 3 | 1152 |
| 同上 | `maxSheets=3 + overflow stop` | 12 | 3 | 1152 |
| 同上 | `cutPair` 开 | 79 | 17 | 6528 |
| 同上 | `a=1.5` | 17 | 14 | 5376 |
| 11 秒 1080p 测试片 | 默认 `a=0.3` | 18 | 2 | 768 |

对照旧版（800×450 一张 233 token）：**同样的张数，1080p 之后成本约 +65%**，换来的是 4×4 每格从 200×112 变成 480×270。

## 安装

前置条件只有一个：**ffmpeg**。

```bash
dsh plugin --profile web add dsh-video-understanding
```

装完重启 `dsh web`。

`ffprobe` 有就更好（拿结构化元数据最准），**没有也能跑**：缺它的时候探测退回解析 `ffmpeg -i` 打印的元数据。只装过 `pip install imageio-ffmpeg` 的环境就属于"有 ffmpeg、没有 ffprobe"，这条路是特意留的。

找 ffmpeg 的顺序：配置里的 `ffmpegPath` → `DSH_FFMPEG_PATH` / `FFMPEG_PATH` → `~/.dsh/bin/ffmpeg/` → winget 的 Links 目录 → PATH。往 PATH 里加目录要重启宿主才生效，所以插件会先自己看一眼那几个常见位置。

## 配置

写在 profile 的 `cordis.patch.yml` 里：

```yaml
- id: video-understanding
  name: dsh-video-understanding
  config:
    # ffmpegPath: D:/ffmpeg/bin/ffmpeg.exe      # 也认 DSH_FFMPEG_PATH / FFMPEG_PATH
    # ffprobePath: D:/ffmpeg/bin/ffprobe.exe    # 也认 DSH_FFPROBE_PATH / FFPROBE_PATH
    a: 0.3                # 攒够几个满屏变化落一帧（解析用 0.3，省 token 用 1.5 以上）
    t: 1                  # 密度窗口（秒）
    maxGap: 5             # 强制补帧间隔（秒）
    multiCross: true      # 允许一个分析间隔内多个时刻
    cutPair: false        # 硬切取前后两帧
    scanFps: 10           # 分析帧率
    longSide: 120         # 分析图长边
    block: 4              # 方块边长
    blockThreshold: 8     # 块级阈值（0~255）
    maxSheets: 5          # 单次交付的图片张数上限（一个拼图算一张）
    overflow: thin        # thin 全片变稀 / stop 看到上限就停
    quality: 3            # JPEG -q:v，2 最好 / 31 最差
    burn: time            # time / index / none
    fontFile: C:/Windows/Fonts/consolab.ttf
    cacheDir: ~/.dsh/cache/video-understanding   # 可改成任意绝对路径
    # transcriptCommand: ["D:/asr/.venv/Scripts/python.exe", "D:/asr/run.py", "{input}", "--out", "{output}"]
```

烧字需要这份 ffmpeg 带 `drawtext`（Gyan 等完整构建有，`imageio_ffmpeg` 那种精简构建没有）。探不到就自动关掉烧字，并在清单里如实说明。

## 字幕

它**不自带 ASR 引擎**，音频这条路走现成的，按代价从低到高：

1. `transcriptFile` 传入 SRT / VTT / JSON（`[{start,end,text}]` 或 whisper 的 `{segments:[...]}`）
2. 没传就读视频内嵌字幕轨，导出成 SRT 再解析
3. 再没有就跑 `transcriptCommand` 配的外部转写命令
4. 都没有就是 `transcript: none`

三条路都带毫秒级时间码，并与画面窗口对齐；解析结果会**按时间排序**，乱序的字幕文件不会把先后说反。

外部命令只收**数组**，不收字符串：

```yaml
config:
  transcriptCommand:
    - D:/asr/.venv/Scripts/python.exe
    - D:/asr/run.py
    - "{input}"
    - --out
    - "{output}"
```

理由是字符串要走 shell 才带得动占位符，而路径里的空格、引号、`&` 在 shell 里各有各的坏法。数组由宿主直接交给子进程服务，不经过任何 shell，`{input}` / `{output}` 在**元素级别**替换。两个占位符缺一个，这条配置就不生效。

命令失败**不会瞒着**：清单里会写 `transcript: none (transcript command failed: ...)`，而不是装作"本来就没台词"。

## 已知限制

- **分析帧率决定变化率的分辨率**。0.1 秒以内的变化在 10 fps 上看不到；要更细就把 `scanFps` 提到 20–30（花的只是解码时间）。
- **窗口边界会把一个突变拆到两个窗口**。0.99 秒处的一个跳变可能被切成 2 帧 + 1 帧，多出一张图。这是固定 `t` 秒窗口的代价。
- **只能分辨"瞬时 / 渐变"**。游程长度分不出淡入淡出、划像、缩放、快速运镜的区别 —— 那要看图判断，算法不替你说。
- **画面内小于约 1 个方块（≈1/30 宽）的改动**在分析图上会打折。`longSide` 提到 160 能找回一部分。
- **1/8 级别的格子认不出字幕和脸**。这是格子的物理尺寸决定的，该用 `video_closeup`。
- **扫描要解码全长**。90 分钟的片子第一次要跑几分钟，之后走缓存。
- **`tile` 只按连续文件名读**。取帧有失败时脚本会把成功的重排成连续序列，清单写的是重排后的格号，时间码是真实的。
- **淡入淡出的黑帧不再主动躲开**（0.3.1 会躲）。现在按窗口均匀重取，过渡里的黑帧是转场的一部分，躲掉反而看不到转场怎么做的。
- **单帧不再打包**（0.5.0 起）。一帧一张图，所以长片安静段（每几秒一帧）的图数会比过去多得多，必须靠 `maxSheets` 和 `overflow` 兜住。
- **单张图固定 1080p**。每张 384 token，比过去的 800×450（233）贵约 65%，换来 4×4 里每格 480×270 的可读性。

## 开发

```bash
npm test                               # 71 项：纯函数 + 工具契约 + 渲染
node scripts/smoke.mjs [视频]          # 端到端：造测试片、跑三个工具、比交付形态
node scripts/verify-host-contract.mjs  # 用宿主自己的校验器验 schema
```

`npm test` 不需要 ffmpeg，也不需要装进 DSH。`smoke.mjs` 需要 ffmpeg；给它一个视频路径就会对那部片子再跑一遍对比。
